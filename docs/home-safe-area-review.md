# 首页安全区复核（2026-10-28）

## 本次截图与边界

用户截图中底部“常亮未开启…”提示只显示上半截，顶部展示操作另占一排。截图显示 `2.5.0+64`，而当前源码为 `2.5.1+14`；不能据此把截图当成当前构建的真机验收结果，也不能仅靠图片推断手机上的 `visualViewport` 数值。

网页宿主已按 `web/viewport.js` 的最终安全矩形定位。主屏幕模式使用完整 CSS viewport，再扣一次 CSS safe-area；普通标签页使用 visual viewport。不要再给 Flutter 嵌入根增加同一组设备安全区，否则会回归此前的双重扣减。固定 Flutter 3.47.5 SDK 的 `CustomElementDimensionsProvider` 按宿主 `clientWidth/clientHeight` 计算尺寸，键盘 inset 为零。

本次复核未发现足以支持替换该策略的新证据，因此不更改宿主测量、键盘处理、缩放保护或横竖屏重测。首页提示应放入正常布局流，按实际文字高度占位，而不是在内容之上悬浮并依赖固定尾部空位。

## 回归验证

- 既有 15 项 `test_web/viewport.test.mjs` 覆盖安全区只扣一次、主屏幕键盘、横屏、恢复、缩放及零尺寸保护。
- 新增 `test/orientation_safe_area_test.dart`：三轮手动旋转与恢复时安全边只旋转一次；网页宿主已经扣除安全区时，Flutter 层只使用界面最小边距，不再次扣设备安全区。
- 上述模拟不能证明真实 iPhone PWA 已修复。发布后仍须在原设备更新到对应构建，分别验证冷启动、横竖屏、后台恢复、键盘收起及底部完整文字。
